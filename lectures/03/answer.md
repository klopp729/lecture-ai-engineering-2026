# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 質問：「AIE2026の講座の宿題にある『3レベル』とは何ですか？」
  - 第1回（app.ask）：AIE2026を「AIエンジニア育成講座などを指すと推測」と前置きし、講座固有の定義を知らないまま、一般的な3段階（レベル1 基礎・レベル2 応用・レベル3 発展）の例をもっともらしく示した。「どれか1つで完了」というルールには触れず、「案内ページを読む」「講師に質問する」よう勧めていた。
  - 第3回（app.agent）：「基礎・実装・発展の3つで、どれか1つに取り組めば完了」と、data/glossary.json の homework-levels の定義どおりに答え、最後に「関連する回：第1回」を付けた。

- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 質問「LoRA とQLoRAの違いは？」で、`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。

- 1つの質問での LLM 呼び出し回数（`requests`）：
  - LoRA/QLoRA の質問：requests=2, tool_calls=2, input_tokens=1196
  - 確認問題の質問：requests=2, tool_calls=1, input_tokens=941

- 追加したツールと、docstring に書いた説明：
  - ツール：`make_quiz(lecture: int) -> str`
  - docstring：「指定した回の用語から1つを選び、確認問題と答えを返す。『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う。」
  - 実装：load_glossary() から指定した回の用語を集め、random.choice で1つ選ぶ。定義を示して用語を答えさせる問題にし、問題と答えを JSON で返す。用語が無い回（lecture=0 など）ではエラーにせずメッセージを返すので、pytest のダミー引数でも落ちない。

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - app/tools.py の search_glossary の docstring「query には調べたい用語を1つだけ入れる（例: "LoRA"）」を「まとめて入れる（例: "LoRA QLoRA"）」に変え、「RAGとファインチューニングの違いは？」を --trace 付きで変更前・変更後それぞれ2回実行して比べた。
  - 用語集に RAG の項目は無い（ファインチューニングの定義文に1回出てくるだけ）。また search_glossary("RAG") は、「一致率」の別名 inter-rater agreement に部分一致し、無関係な「一致率」を返す。
- 結果：
  - 変更前（2回とも同じ）：('RAG') と ('ファインチューニング') を同時に検索 → ('RAG') をもう一度検索。tool_calls=3, requests=3, input_tokens=2455。一致率は回答に使わなかった。RAG は1回目は「用語集に定義がない」と断って自分の知識で補足、2回目は「見つからなかった」とだけ書いた。
  - 変更後1回目：('RAG ファインチューニング') → ('RAG')。tool_calls=2, requests=3, input_tokens=1728。「用語集に直接登録されていない」と断って RAG を説明した。
  - 変更後2回目：('RAG ファインチューニング') のみ。tool_calls=1, requests=2, input_tokens=956。「用語集にはない」と伝えず、「一般的に」として自分の知識で RAG を説明した。
- 気づき・疑問：
  - docstring の一言で、モデルの検索の仕方（回数・引数）がはっきり変わった。
  - まとめて検索すると呼び出し回数とトークンは減ったが、動きが揺れやすくなり、「用語集にない」と正直に伝える点が弱くなった。効率と、根拠に基づく正直さのトレードオフがある。
